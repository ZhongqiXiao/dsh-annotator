# 指哪改哪 · UX 评估与优化方案（v10 提案）

评估对象：`lib/client.js`（右侧栏面板，983 行）与 `lib/overlay.js`（页面内拾取浮层，301 行）。
方法：逐行审读两处 UI 实现 + WCAG 对比度实测 + 状态机/线框图还原。GUI 需桌面端凭据，本轮以代码与实测色值为证据，未做人眼截图评审。

## 1. 结论摘要

| 维度 | 现状评分 | 一句话判断 |
|---|---|---|
| UI 样式 | 6.0 / 10 | 信息密度好，但三套颜色并存、字号偏小、层级靠蓝底硬撑 |
| 信息架构 | 5.5 / 10 | 连接 / 标注 / 发送三阶段 + 四个杂项动作压在同一条竖列，首屏被控件占满 |
| 交互 | 6.0 / 10 | 主链路可用，但「卡片 ↔ 页面元素」没有回指，插入结果反馈是一次性文本 |
| 响应式 | 5.0 / 10 | 全固定像素，无容器查询；窄侧栏下页脚与卡片必然被挤压 |
| 无障碍 | 4.5 / 10 | 无 label、无 aria-live、无 focus-visible、浮层卡片不是 dialog |

综合约 **5.5 / 10**：能完成任务，但「找得到、看得懂、错不了」三层里，第一层稳定、后两层靠用户猜。

## 3. 目标信息架构（v10）

```
┌ 指哪改哪   ● 已连接 · localhost:3000   [⋯] ┐   ← 状态胶囊 + 溢出菜单
├───────────────────────────────────────────┤
│ [http://localhost:3000______] [打开]       │   ← 连接区（已连接时收起为单行）
│ 标签页: [首页] [详情] [设置]                │   ← 仅多标签时出现
├───────────────────────────────────────────┤
│  ┌ 标注模式 ───────────────  [ 开关 ] ┐    │   ← 主操作：Switch + 已标注计数
│  │ 在页面里点击元素，写一句想怎么改    │    │
│  └────────────────────────────────────┘    │
├───────────────────────────────────────────┤
│  #1  button.btn-primary   · localhost:3000 │   ← 卡片：序号 + 元素 + 所属页
│  [缩略图] 文本摘要…         [定位][插入][⋯] │
│  selector 单行（可复制）                    │
│  评论：[已保存 ✓]                          │
├───────────────────────────────────────────┤
│ 插入形态 [引用|详细] ⓘ     [ 全部插入（3）] │   ← 底部：格式 + 唯一主 CTA
└───────────────────────────────────────────┘
```

要点：
1. 「连接 → 标注 → 发送」三阶段只在各自激活时占面积，其余折叠。
2. 全局只有一个主 CTA；复制/清空/关闭浏览器进 `⋯`。
3. 卡片成为可回指的实体（定位、复制选择器、删除、撤销）。

## 4. 设计规范

| 类别 | 规范 |
|---|---|
| 间距 | 4 / 8 / 12 / 16（4pt 栅格） |
| 圆角 | 控件 6px，卡片 10px，胶囊 999px |
| 字号 | 正文 13 / 辅助 12 / 标签 11（最小 11，不再用 10） |
| 颜色 | 语义变量：`--vp-accent`（蓝）、`--vp-danger`、`--vp-ok`、`--vp-warn`；浅色 `#1f6feb/#cf222e/#1a7f37/#9a6700`，深色 `#79b8ff/#ff7b72/#3fb950/#d29922` |
| 焦点 | `outline: 2px solid var(--vp-accent); outline-offset: 2px` |
| 动效 | 150ms ease-out；`prefers-reduced-motion` 下关闭 |
| 图标 | 16px 线性图标（定位/插入/删除/复制），与文字并排 |

## 5. 交互规格

**状态机**（面板）

| 状态 | 连接区 | 主操作 | 内容区 |
|---|---|---|---|
| idle（未启动） | 地址框 + 「打开」主按钮 | 禁用，提示「先打开浏览器」 | 三步引导（可点） |
| starting | 按钮 loading + 进度文案 | 禁用 | 骨架 |
| ready | 地址框 + 标签条 | Switch 可用 | 卡片列表 / 空态 |
| picking | 同上 + 状态胶囊「标注中」 | Switch 开 + 计数 | 卡片实时追加 |
| error | 地址框 + 「重试」 | 禁用 + 原因 | 保留已有卡片 |

**反馈**：`toast(kind, message, action?)`，成功 3s 自动消失、可手动关；降级（截图未附上）常驻直到下一次操作；失败带「重试」。

**键盘**：`Alt+A` 开关标注 · `↑/↓` 卡片间移动 · `Ctrl/⌘+Enter` 插入全部 · `Esc` 退出标注 · 焦点环全程可见。

**错误**：错误条常驻并可关闭，带错误码与建议动作；网络失败不吞掉已有列表。

## 6. 响应式规格

| 容器宽度 | 布局 |
|---|---|
| ≥ 340px | 卡片横向（缩略图 96×72 + 内容），页脚单行 |
| 300–340px | 卡片横向但缩略图 72×54，页脚两行 |
| < 300px | 卡片纵向（缩略图通栏 16:9），页脚主 CTA 独占一行 |

实现用 `@container`（面板根节点 `container-type: inline-size`），不依赖视口；浮层卡片 `width: min(308px, calc(100vw - 16px))`。

## 7. 无障碍验收清单

- [ ] 所有输入控件有可见 label 或 `aria-label`
- [ ] 状态与 toast 有 `role="status"` / `role="alert"`
- [ ] 所有可交互元素有 `:focus-visible` 环，Tab 顺序符合视觉顺序
- [ ] 浮层卡片 `role="dialog" aria-modal="true"`，Esc 关闭、焦点还原
- [ ] 文本对比度 ≥ 4.5:1（大字 ≥ 3:1），已按第 4 节色值修正
- [ ] 目标尺寸 ≥ 32×32px
- [ ] 200% 缩放与 320px 视口下无横向滚动
- [ ] 不依赖颜色单一编码状态

## 10. 保留的优势

1. 状态门控克制：未就绪不显示标注按钮，比"全亮"式面板省心。
2. 卡片「缩略图 + selector + 文本」三元组信息密度优秀，一眼能确认对象。
3. 空态给了编号步骤，方向感清楚。
4. 页面内悬停高亮 + 尺寸标签 + 底部计数徽章，是同类工具里做得扎实的部分。
5. 引用/详细双形态是很好的渐进披露设计，只是位置放错了。

## 11. 验证方法

1. **静态**：`npm run verify`（node --check + eslint + node --test）保持全绿。
2. **对比度**：对第 4 节全部色值跑 WCAG 计算脚本，门槛 4.5:1。
3. **响应式**：在 280 / 320 / 400 / 520px 四档容器宽度下截图走查（可用临时 HTML 壳 + 同一份 CSS 渲染）。
4. **键盘**：不碰鼠标完成「打开页面 → 标注 2 个元素 → 插入」。
5. **回指**：插入前点「定位」，确认页面元素闪烁并在视口居中。
